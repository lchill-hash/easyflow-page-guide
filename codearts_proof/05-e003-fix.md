# 05 — EF-E003 点击授权链路修复

## 1. 问题现象

在 `bjsjs.gov.cn` 验收页点击 EasyFlow 工具栏图标后，侧边栏打开，但显示：

```text
EF-E003 未获得当前页面访问授权，请点击扩展图标后重试
```

用户明确要求：只修复“图标点击 → activeTab 授权 → 注入 content.js → 打开侧边栏 → 读取当前页”链路；不改页面匹配功能；不增加 `<all_urls>` 权限。

## 2. 根因分析

原实现同时存在两条入口：

```ts
chrome.sidePanel.setPanelBehavior({ openPanelOnActionClick: true });
chrome.action.onClicked.addListener((tab) => {
  chrome.sidePanel.open({ tabId: tab.id });
});
```

`openPanelOnActionClick: true` 时由浏览器接管图标点击并直接打开侧边栏，`chrome.action.onClicked` 不触发。实际链路退化为：

1. 用户点击图标；
2. 浏览器自动打开侧边栏；
3. 扩展没有在点击回调中执行注入；
4. 侧边栏首次 `EF_COLLECT` 才调用 `ensureInjected`；
5. 此时 `activeTab` 未按预期落到扩展的注入路径，`executeScript` 返回权限类错误；
6. `toEfError` 把该错误统一映射为通用 `EF-E003`，真实 Chrome 错误只存在 `detail` 中，界面此前未展示。

结论：`setPanelBehavior(true)` 与 `action.onClicked` 并存造成入口竞争与注入时机偏差；首次注入不应等到侧边栏首次采集。

## 3. 修复内容

### 3.1 只保留一个图标点击入口

文件：`src/background/index.ts`

- 移除 `setPanelBehavior({ openPanelOnActionClick: true })`。
- 显式设置为 `false`，避免旧版本持久化的自动打开行为继续拦截 `action.onClicked`：

```ts
chrome.sidePanel.setPanelBehavior({ openPanelOnActionClick: false });
```

- 在 `chrome.runtime.onInstalled` 时再次设置为 `false`。
- 唯一入口为 `chrome.action.onClicked`；在点击回调中**立即**调用：
  1. `chrome.sidePanel.open({ tabId })`；
  2. `primeInjection(tabId)` 预注入 content.js。
- `sidePanel.open` 失败时输出 `[EF] side-panel-open-failed` 诊断日志。

### 3.2 点击时预注入与并发去重

文件：`src/background/injector.ts`

- 新增 `primeInjection(tabId)`：点击回调中立即触发 `ensureInjected`，不再等用户点“重新读取页面”。
- 新增 `injectionLocks`：同一标签页的点击预注入与侧边栏首次采集共享同一个注入 Promise，避免并发重复注入。
- 新增 `lastInjectionErrors`：记录最近一次真实注入失败。
- 注入失败时 `console.warn("[EF]", { phase: "content-injection", code, detail })`，并保留错误对象。
- `toEfError` 保留真实 Chrome 错误文本到 `EfError.detail`。
- 注入成功或重新注入成功后清除该标签页的历史错误。

### 3.3 真实注入错误进入诊断信息

文件：`src/background/router.ts`

- 新增 `withInjectionDetail(tabId, error)`：若当前错误无 `detail`，则附加 `lastInjectionErrors` 中的真实错误文本。
- `EF_COLLECT`、`EF_HIGHLIGHT` 的所有注入失败返回均经过该函数。
- 不再只返回通用文案；`detail` 会随错误对象到达侧边栏。

文件：`src/sidepanel/components/StatusBanner.tsx`

- 错误横幅新增“诊断：<真实 Chrome 错误>”展示。

文件：`src/sidepanel/diagnostics/RunLog.tsx`、`src/sidepanel/App.tsx`

- “运行诊断”新增“最近一次错误 EF-Exxx：<detail 或 message>”。
- 仅展示错误诊断，不展示页面正文。

文件：`src/sidepanel/styles/sidepanel.css`

- 新增 `.ef-banner-detail`、`.ef-diagnostic-detail` 样式，长错误文本可换行。

### 3.4 错误分类收紧

文件：`src/shared/errors.ts`

将 `EF-E003` 的匹配条件从宽泛的 `permission` 收窄为：

```text
activeTab | manifest must request permission | missing host permission |
not granted | not allowed to access | denied
```

其他注入错误不再被一律吞并为 E003，而按 Chrome 真实错误落到 `EF-E002`、`EF-E004`、`EF-E007` 或 `EF-E005`，并保留 `detail`。

- 增加 E003 仍出现时的重新加载/移除重载步骤。

## 7. Chrome 重新加载与网页复测步骤

1. 确认 `dist/` 为最新构建产物。
2. 打开 `chrome://extensions`。
3. 找到 EasyFlow：
   - 先点击“重新加载”；
   - 若仍出现 E003，点击“移除”，再点“加载已解压的扩展程序”，选择 `dist/`。此步骤可清除旧版本持久化的 `openPanelOnActionClick` 行为。
4. 打开或刷新主验收页：
   ```text
   https://www.bjsjs.gov.cn/gongkai/zwgkpd/ztzl/2024/wqfw/lnrzq/cjcs/202402/t20240229_79299.shtml
   ```
5. 确认该网页标签页处于活动状态。
6. **直接点击工具栏 EasyFlow 图标**；不要通过浏览器右上角侧边栏菜单首次打开。
7. 预期：侧边栏打开，显示 `www.bjsjs.gov.cn`、页面标题与可见条目数，不再显示 E003。
8. 若仍失败：
   - 展开侧边栏“运行诊断”，记录“最近一次错误 EF-Exxx：<真实错误>”；
   - 打开 `chrome://extensions` → EasyFlow → “Service Worker” → “检查视图” → Console；
   - 查找 `[EF]` 日志：`content-injection`、`click-preflight`、`side-panel-open-failed`；
   - 将错误详情与 Chrome 版本反馈，用于继续定位。
9. 成功后按原流程输入目标、点击“分析当前页”、点击“查看原文”完成复测。

# EasyFlow 页面陪办助手

EasyFlow 是一个运行在**用户主动打开的真实第三方网页**上的聊天式浏览器指引扩展。用户说一句话，它会判断：

- 直接回答当前页面上能查到的信息；
- 追问缺失的目标；
- 给出一个可执行的下一步，并允许“指给我看”；
- 或者坦诚说明当前页面没有依据。

> 当前为**本地规则演示**，未接入在线模型。扩展内没有模型密钥，也不会发起模型请求。语音输入代码已加入，但在当前实测电脑上未通过：麦克风已授权，浏览器服务识别报网络错误，本机中文资源安装返回失败。文字输入可正常使用。朗读功能仍需真实设备验收。

## 当前进度

- 已在真实网页演示：政务指南问答与原文定位；Cal.com 日期、动态可用时段的逐步指引及预约成功页识别；普通/长者关怀模式。
- 待修复与验证：用户报告高亮持续闪烁，需按真实 Chrome 表现排查；语音输入不可用；朗读尚未完成真实设备验收；跨更多网站的灵活理解尚未接入运行时模型。
- `codearts_proof/` 保存各轮实现与测试说明。自动测试、真实浏览器验收和待验项目在这些记录中分别标注。

## 技术栈

- Manifest V3 + TypeScript + React 18
- esbuild 三入口：后台 ESM、content IIFE、侧边栏 ESM + CSS
- 本地规则对话引擎 + 可替换 `DialogueEngine` 接口
- 无 UI 框架、无路由库、无远程 SDK

## 安装与构建

要求 Node.js 20+、npm 10+。

```bash
npm install
```

依赖已在本地且网络受限时：

```bash
npm install --offline
```

构建：

```bash
npm run build
```

构建链：`tsc --noEmit` → 清空 `dist/` → 生成图标 → esbuild 三入口 → 复制清单/HTML → 清单与门禁校验。

产物位置：`D:\hwproject\translator\dist`。

其他命令：

```bash
npm run typecheck
npm run selftest
npm run verify
```

## 在 Chrome 中加载

1. 打开 `chrome://extensions`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择 `dist` 目录。
5. 建议把 EasyFlow 固定到工具栏。

## 使用方式

### 1. 打开与自动读取

打开目标网页后点击 EasyFlow 图标。侧边栏会先显示欢迎语和输入框，再自动读取当前页；不需要先点任何工作流按钮。

页面状态只显示一行：

- 正在读取当前页面…
- 已看到 `<域名>` 的页面
- 无法读取当前页面
- 页面已变化，正在核对

读取失败时，聊天里会说明原因并提供“重试”。

### 2. 直接回答

主验收页可以输入：

```text
高龄津贴谁能申请
```

预期：

- 1—3 句可理解回答；
- 回答下方有可折叠“网页依据”；
- 展开后显示原文片段和“在网页中查看”；
- “在网页中查看”滚动并高亮真实文字，约 4 秒后移除。

继续追问：

```text
在哪里线下办理
那需要带什么
```

系统会沿用上一轮的对象继续回答，不要求用户重新解释目标。

如果当前页没有信息，会明确说“当前页面没有找到这项信息”，不会补写金额、地址、电话或办理结果。

### 3. 逐步陪办

建行网点查询页可以输入：

```text
第一次办借记卡，先找营业网点
```

预期：

- 只给一个下一步，例如“先选择所在城市或地区”；
- 消息内嵌“指给我看”；
- 点击后只滚动、高亮真实控件，不点击、不聚焦、不填写；
- 用户自行完成后可以点“我已完成”，或等待 DOM 变化触发复审；
- “我找不到”会重新定位控件；
- “我点错了”会基于当前页重新规划；
- “换一个任务”会结束旧计划并重新询问目标。

步骤完成判定只认：

- 页面文本/控件变化；
- 页面地址变化；
- 用户明确点“我已完成”。

不会用定时器假装完成。无法确认时会说：“我还不能确认这一步是否完成”。

### 4. 网页切换

切换标签页、刷新或导航后：

- 聊天记录保留；
- 旧引用标记为已失效；
- 当前步骤转为待复核；
- 扩展重新读取当前页，再决定是否继续下一步。

### 5. 建行申请页只读边界

可以问：

```text
这个页面要填什么
指给我看手机号那一栏
```

扩展只会引用字段标签与页面解释文字，并高亮标签；不会读取 `input.value`。

会拒绝：

```text
帮我填身份证号
帮我勾选协议并提交
验证码是多少
```

这些操作需要用户本人完成，扩展不代填、不代勾选、不代提交、不索取验证码。

## 规则演示与在线模型边界

- 当前 `DialogueEngine` 只有规则实现，界面固定显示“本地规则演示，未接入在线模型”。
- `ModelDialogueEngine` 只是占位，状态恒为 `not-configured`，零请求。
- 扩展内没有 API Key，不直连模型厂商。
- 未来若接入，只允许通过本机代理，由代理侧从环境变量读取密钥；代理契约记录在 `src/shared/privacy/redact.ts` 的 `PROXY_CONTRACT`。
- 当前缺少的配置：可用模型端点、模型名、授权方式、代理运行环境。未配置前不会开启模型模式。
- 不向模型发送：`input.value`、姓名、证件号、手机号、银行卡号、验证码、密码、完整页面 HTML。
- 语音输入已实现浏览器服务、本机能力检测及授权页，但当前实测设备上尚不可用；文字输入始终可用。朗读使用浏览器语音合成，真实设备效果仍待验收。

## 权限与隐私

清单权限仍为四项：

- `activeTab`
- `scripting`
- `sidePanel`
- `storage`

未申请：

- `host_permissions`
- `<all_urls>`
- 静态 `content_scripts`
- `tabs`
- 麦克风相关权限

只读约束：

- 采集只调用只读 DOM API；
- 不读取输入框/文本域/下拉框的 `value` 或选中值；
- 只保留按钮 `button/submit/reset` 的 `value` 作为按钮文字兜底；
- 不修改原网页节点文本、属性、结构；
- 唯一页面写入是临时高亮宿主，约 4 秒后移除；
- 不点击、不聚焦、不勾选、不填写、不提交、不处理验证码。

会话与存储：

- 页面正文、语义段、引用、聊天、步骤只存在侧边栏内存；
- `chrome.storage.local` 只保存用户目标 `easyflow.goal`（≤200 字）；
- 关闭侧边栏即结束会话，重开重新读取当前页。

## 已知限制

- 本轮为规则匹配，不保证语义理解；换一种问法可能命中不足。
- 只读取主文档，不进入 iframe；地图/内嵌框架内的结果读不到。
- 网页依据按单条引用定位；标题+正文批量高亮的消息字段已预留，但本轮 UI 未启用。
- 跨域下一步只给文字说明，不自动导航、不新开标签。
- 登录、实名、验证码、提交、支付等步骤停止推进，需要用户本人完成。
- 懒加载、分页、站点改版可能导致控件找不到；会说明真实原因，不假装成功。
- `activeTab` 受浏览器安全模型约束：切换标签页或跨源导航后通常需要重新点击扩展图标。
